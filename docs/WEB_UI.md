# OFS Web UI

The OFS web layer is explicit. A normal `.ofs` file is just an OFS program; a site file declares web intent with `attach {webui}` and calls `webui.serve(...)`, `serve_html_forever(...)`, or `serve_html_once(...)`.

## Runtime Pieces

| Module | Purpose |
|---|---|
| `ofshtml` | OFS-native markup DSL; source stays in OFS while output becomes browser HTML |
| `webserver` | HTTP response helpers and native static response server |
| `webui` | Declarative page/component helpers that generate HTML and style |
| VS Code `Go Live` | Runs only files that look like OFS site files |

## Example

```ofs
attach {webui}

core main() {
    forge body = webui.hero(
        "OFS Web",
        "A page generated and served by OFS.",
        webui.button("Start", "#")
    )

    webui.serve(8080, "OFS Web", body)
}
```

## Design Rule

OFS does not treat every source file as a website. Web mode is a library-level DSL.

For raw document structure, use `ofshtml`:

- `ofshtml.document(...)`
- `ofshtml.section(...)`
- `ofshtml.div(...)`
- `ofshtml.a(...)`
- `ofshtml.code_block(...)`

For app/site components, use `webui`:

- `webui.nav(...)`
- `webui.hero(...)`
- `webui.button(...)`
- `webui.panel(...)`
- `webui.grid(...)`
- `webui.card(...)`
- `webui.page(...)`
- `webui.serve(...)`

The current layer generates browser HTML from OFS source. Users do not need to write a separate CSS file for basic pages, and the official GitHub Pages site is generated by `ofs/site/build_site.ofs`.

## Current Limitations

- The server serves a static generated response.
- Routing and request handlers are not implemented yet.
- Live reload is command-level only; it starts the OFS program but does not hot-swap the process.
- `webui` is experimental and should remain separate from normal console/native OFS code.
