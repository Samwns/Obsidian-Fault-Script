    namespace webview8 public functions75%ofs/stdlib/android_webview.ofs

    OFS Standard Library — android_webview: WebView em tela cheia, 100% OFS (JNI)

    attach {F:android_webview.ofs}
webview.open("file:///sdcard/Jogo/", html, shim_js)  // false se falhar
webview.poll()            // 1x por quadro: false quando o usuario fechou (voltar)
webview.eval("js...")     // evaluateJavascript sem retorno
webview.title()           // document.title da pagina (canal JS -> OFS)
webview.close()           // destroi a WebView

    Nenhuma classe Java propria: a WebView fica num android.app.Dialog (janela propria; a NativeActivity toma a superficie da janela principal, entao uma View adicionada a ela nao seria desenhada). O botao voltar fecha o Dialog sozinho (cancelable); poll() percebe por Dialog.isShowing(). Como nao ha WebViewClient/ValueCallback proprios: - o shim e injetado como <script> no inicio do HTML (loadDataWithBaseURL); - o retorno do JS para o OFS vai pelo document.title (webview.title()). So na thread principal (callbacks do android.ofs).
