    #__ofs_arr_num

    internal
    vein __ofs_arr_num(n: stone) -> void

    Cabecalho do array (4 palavras de 8 bytes): [data, len, cap, elem_size]. O codegen (llvmgen) le/escreve esse layout direto no caminho rapido de a[i], a[i] = v, ofs_array_push e ofs_array_len (elem_size == 8); estas funcoes ficam para o caminho lento (fora dos limites, outro elem_size, crescimento). O runtime e compilado sem otimizacao (-O0): por isso as funcoes leem o cabecalho com fracture em vez de chamar _load_stone/ofs_array_len a cada campo. Cabecalho e dados iniciais num bloco so (uma alocacao e uma liberacao por array): os dados comecam logo depois do cabecalho (arr + 32). Ao crescer, os dados vao para um bloco proprio; o inicial nunca e liberado sozinho (faz parte do cabecalho). Erro de acesso ao array: mensagem no stderr (fd 2) e exit(1). Antes era so exit(1), e o programa terminava mudo. O interpretador (ofs run) imprime o mesmo texto. Sem alocar (como ofs_out_of_memory).

    Parameters

    nstone
