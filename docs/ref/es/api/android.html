    OFS stdlib — android: backend NativeActivity em OFS puro (aarch64, API 26+)

    attach {F:android.ofs}

    vein android_event(ev: stone) -> void {
    if (ev == android.EV_FRAME) { ...desenha com android.lock/unlock_post... }
    if (ev == android.EV_BACK) { android.finish() }
}

    Nao usa o android_native_app_glue nem nenhum .c: este arquivo exporta ANativeActivity_onCreate e preenche activity->callbacks com o endereco de veins OFS (fault_addr). Tudo roda na thread principal do Android:

    - ciclo de vida: callbacks do ANativeActivity;
- entrada: AInputQueue_attachLooper no looper da thread principal;
- frames: AChoreographer_postFrameCallback, reagendado so quando alguem
  pede (`request_frame`) ou com `android.continuous = true`.

    Sem pthread, entao o runtime magma (que nao e thread-safe) fica seguro. Trabalho longo deve ser feito em pedacos, um por EV_FRAME.

    O programa define vein android_event(ev: stone) -> void (contrato fixo, declarado abaixo como extern) e le o estado em android.*. A .so precisa ser linkada com -Wl,-init,__ofs_init_globals (nao ha main()). ofs build --target android ja faz isso.

    Convencao de ABI: inteiros C de 32 bits chegam como stone com o topo indefinido/zerado; use android.s32() para recuperar o valor com sinal.
