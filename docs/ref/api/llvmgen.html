    #struct_layout

    llvmgen
    vein struct_layout(field_types: Array<obsidian>, offsets: Array<stone>) -> stone

    Layout C de um monolith: FONTE UNICA para o codigo nativo (tamanho do ofs_alloc; o %T = type {...} do LLVM da os mesmos offsets) e para o interpretador, que guarda monoliths em memoria crua com este layout (passar &s ou s ao C funciona igual nos dois modos).     #emit_loop_laa_guard

    llvmgen
    vein emit_loop_laa_guard() -> void

    Marca cada corpo de loop com um asm vazio que so toca memoria inacessivel: nao gera instrucao e a analise de alias o ignora (LICM/GVN seguem iguais), mas faz a LoopAccessAnalysis desistir do loop. Sem isso o LLVM 14 com -opaque-pointers da segfault em RuntimePointerChecking::insert (LoopLoadElimination no -O1, LoopVectorize no -O2) em qualquer loop sem chamadas que precise de checagem de alias em tempo de execucao, p.ex. *(b.data + pos) = ... relendo b.data a cada volta (strbuf.append_int).
