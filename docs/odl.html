ODL nao e HTML

ODL e uma linguagem de documentos com tokens, componentes, Markdown e pontos de comportamento proprios. HTML e um target opcional do compilador para navegadores e hospedagens existentes; nao define a sintaxe nem o modelo da ODL.

Arquivos .odl continuam sendo a fonte oficial. A sintaxe indentada atual permanece valida; a forma com chaves e argumentos tipados e uma evolucao compativel para componentes mais fortes.

Gramatica e estrutura

Hoje cada linha possui uma forma, qualificadores opcionais de classe/id e argumentos entre aspas. A indentacao determina parentesco. A forma tipada tambem aceita blocos com chaves, chamadas com parenteses e fechamento principal com end, sem remover a gramatica atual.

page.odl atual
page "OFS Web" "pt"
skin "theme.oes"
flow
  deck.topbar
    title1 "OFS Web"
    link.button "Documentacao" "#docs"
  stage#content
    band.docs
      mark "## Documento ODL\nConteudo com **Markdown**."
      tile.status
        text "Componente estrutural reutilizavel"
  spark "app.js"
page.odl tipado
page "OFS Web" "pt"
  skin("theme.oes")

  flow {
    deck.topbar {
      title1("OFS Web")
      link.button("Docs", "#docs")
    }

    stage#content {
      band.docs {
        use Notice(title: "HMR Ativo", status: "success")
      }
    }
  }
end

Componentes ODL

component nome declara uma unidade reutilizavel e use nome cria um ponto de montagem. Quando a assinatura tipada estiver ativa, props como title: String e status: String viram contrato do componente. Se uma versao nova reduzir a forca da tipagem, a regra e manter a tipagem OFS atual.

components.odl atual
component notice
  tile.notice
    title2 "Aviso"
    text "Conteudo reutilizavel"

flow
  use notice
Notice tipado
component Notice(title: String, status: String)
  tile.notice(data-status: status) {
    title2(title)
    text("Componente injetado com tipagem forte e escopo fechado.")
  }
end

Estado, eventos e servidor

ODL define onde comportamento entra. wire carrega script classico, spark carrega modulo, pulse insere comportamento inline e OFS/webserver executa logica nativa no servidor. A meta do target web e gerar componentes reativos pre-compilados que atualizam nos reais diretamente, sem diff de DOM virtual.

Browser

wire, spark e pulse conectam comportamento JS/WASM no build final.

Servidor

OFS e webserver tratam processo, HTTP e dados.

Hot state

O modo dev deve aplicar diff visual sem refresh e sem perder dados digitados.

Targets e hospedagem

O compilador atual possui target web para interoperar com os navegadores existentes. ODL pode ser servido como fonte com MIME proprio, traduzido para inspecao ou compilado para um documento web.

Target e formato de distribuicao nao sao a linguagem. O mesmo principio permite adicionar targets nativos sem redesenhar a gramatica ODL.
