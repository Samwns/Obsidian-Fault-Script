ODL nao e HTML

ODL e uma linguagem de documentos com tokens, hierarquia por indentacao, componentes, Markdown e pontos de comportamento proprios. HTML e um target opcional do compilador para navegadores e hospedagens existentes; nao define a sintaxe nem o modelo da ODL.

Arquivos .odl continuam sendo a fonte oficial. Um projeto pode versionar somente ODL/OES e gerar artefatos no build.

Gramatica e estrutura

Cada linha possui uma forma, qualificadores opcionais de classe/id e argumentos entre aspas. A indentacao determina parentesco. Texto comum e escapado; somente `raw` ignora essa protecao.

page.odl
page "OFS Web" "pt"
skin "theme.oes"
flow
  deck.topbar
    title1 "OFS Web"
    link.button "Documentacao" "#docs"
  stage#content
    band.docs
      mark "## Documento ODL\nConteudo com **Markdown**."
      tile.status
        text "Componente estrutural reutilizavel"
  spark "app.js"

Componentes ODL

`component nome` declara uma unidade reutilizavel e `use nome` cria um ponto de montagem. No compilador atual, componentes sao preservados como templates no target web; composicao OFS tambem pode ser feita por funcoes que retornam `obsidian`.

components.odl
component notice
  tile.notice
    title2 "Aviso"
    text "Conteudo reutilizavel"

flow
  use notice

Estado, eventos e servidor

ODL define onde comportamento entra, mas nao finge que toda aplicacao ja possui um runtime reativo completo. `wire` carrega script classico, `spark` carrega modulo, `pulse` insere comportamento inline e OFS/webserver executa logica nativa no servidor. Estado reativo tipado e hidratacao de componentes ainda sao itens de evolucao.

Browser

`wire`, `spark` e `pulse` conectam comportamento.

Servidor

OFS e `webserver` tratam processo, HTTP e dados.

Conteudo

`mark` integra Markdown sem converter a fonte ODL em HTML.

Targets e hospedagem

O compilador atual possui target web para interoperar com os navegadores existentes. ODL pode ser servido como fonte com MIME proprio, traduzido para inspeção ou compilado para um documento web. GitHub Pages, nginx e CDNs hospedam o target; eles nao transformam ODL em HTML nem mudam a identidade da linguagem.

Target e formato de distribuicao nao sao a linguagem. O mesmo principio permite adicionar targets futuros sem redesenhar a gramatica ODL.
