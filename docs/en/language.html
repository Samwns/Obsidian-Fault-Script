What OFS is

OFS is a self-hosted compiled language. The compiler is written in OFS, emits LLVM IR, and links against a native runtime.

Syntax

Programs use `vein` functions, `forge` bindings, explicit returns, and `core main()` as the entry point.

hello.ofs
vein add(a: stone, b: stone) -> stone {
    return a + b
}

core main() {
    forge result: stone = add(20, 2)
    echo(result)
}

Types

The base types include `stone`, `crystal`, `obsidian`, `bool`, integer widths, arrays, and `monolith` structures.

stonecrystalobsidianboolarraysmonolith

Modules

Libraries are attached with `attach`, keeping native code, standard library modules, and web DSLs in the same model.

attach {math}

Import a standard library module.

attach {F:path/file.ofs}

Import a local OFS file explicitly.

extern vein

Declare runtime or C symbols.

core main()

Define the native entry point.

Low-level modes

Low-level work is opt-in and visible in source. These forms do not make an invalid pointer valid, add garbage collection, or automatically manage an allocation's lifetime.

fracture { ... }

Typed pointer context. Pointer element types are checked, while address validity and lifetime remain the program's responsibility.

abyss { ... }

Explicit raw-work boundary. It does not disable the current parser or type checker and adds no memory-safety guarantee.

bedrock { ... }

Typed machine-adjacent context for regions, lanes, endian helpers, barriers, prefetch, and fault_* intrinsics.

intent fractal

Function intent metadata. The current parser does not implement fractal as a block keyword.

tectonic

Accepted before fracture, abyss, or bedrock. It currently preserves the same block semantics.

Manual lifetime

Cells and regions allocated by bedrock must be released once and must not be read after release.
