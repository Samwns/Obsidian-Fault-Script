# OFS on Android (aarch64)

OFS builds native Android apps **100% in OFS**: the APK carries a `lib<name>.so` compiled from your code and the stdlib, with no Java, no Gradle and no `.c` files. Only system libraries (libc/bionic, libandroid, liblog) are called, through `extern vein`/`rift vein`, the same way libc is used on the desktop.

Tested on a Moto G8 Power (arm64-v8a, Android 11) on 2026-11-06.

---

## Requirements

| Item | Version used | Purpose |
|---|---|---|
| Android SDK | `platforms/android-*` with `android.jar` | `aapt2 link` |
| build-tools | 37.0.0 (`aapt2`, `zipalign`, `apksigner`) | packaging and signing |
| NDK | 29.0.14206865 | `clang --target=aarch64-linux-android26`, sysroot with libandroid/liblog |
| `keytool` (JDK) | any | debug key generation |
| `adb` (platform-tools) | any | `--install` |

Set `ANDROID_SDK` (or `ANDROID_HOME`/`ANDROID_SDK_ROOT`) to the folder that contains `ndk/`, `build-tools/` and `platforms/` (default `~/Android/Sdk`). The newest version of each is used.

`ofscc` must understand `OFSCC_TARGET` (this version onward). If the installed `ofscc` is older, the CLI builds one from the repository source (`OFS_SOURCE=<repo>/ofs`) and caches it in `~/.cache/ofs/android/`.

## Building the APK

```bash
# from an .oal (manifest generated by oalc)
ofs build --target android app.oal -o app-debug.apk

# from an .ofs that defines android_event (manifest: --manifest, or
# AndroidManifest.xml next to the source, or one generated with org.ofs.<name>)
ofs build --target android game.ofs --manifest AndroidManifest.xml

# install and open
ofs build --target android app.oal --install --serial 0064380838
```

What the CLI does (`src/packaging/linux/ofs`, `android_build`):

1. `.oal` → `oalc` → `AndroidManifest.xml` + `<name>_oal.ofs` (see [OAL_REFERENCE.md](OAL_REFERENCE.md));
2. `OFSCC_TARGET=android ofscc` → LLVM IR with `target triple = "aarch64-unknown-linux-android26"` for the app and the `magma` runtime (the runtime is cached);
3. NDK `clang` → `lib<name>.so` with `-shared -Wl,-init,__ofs_init_globals -u ANativeActivity_onCreate -Wl,-z,max-page-size=16384 -landroid -llog -lm`;
4. `aapt2 link` + `zip` of `lib/arm64-v8a/` + `zipalign -P 16` + `apksigner` (key `~/.android/debug.keystore` or one generated in the cache).

The `.so` name comes from `android.app.lib_name` in the manifest. Intermediate files go to `build/android/<name>/` next to the source (or `OFS_ANDROID_BUILD`).

## Live editing on the device (Fault Refract L3)

With the phone on USB (USB debugging on), the app runs on the device and every edit saved on the PC goes into it **without reinstalling or restarting the process**: edited veins are swapped on their next call and globals keep the values they already had.

```bash
ofs refract --remote app.oal                   # build --refract, install, open, connect and watch
ofs refract --remote app.oal --serial 0064380838
ofs build --target android app.oal --refract --install   # just the APK with cells and agent
```

Example: `ofs/examples/refract_android/` (a per-second counter; edit `painel.texto()` in `painel.ofs` and save). PC output:

```text
refract: conectado a org.ofs.refract.demo (pid 16109, geracao 0, porta 7341 -> localabstract:ofs-refract.org.ofs.refract.demo)
refract: alteradas: painel.texto
refract: geracao 1 aplicada no app em 1 ms: painel__texto (6272 bytes, pid 16109)
```

**How it works.**

1. **`--refract` build.** User veins (the main file and local `attach`es; the stdlib is left out) get an exported **dispatch cell** (`@__ofs_cell.<vein>`, a pointer) and every direct call to them loads the cell. The `.so` carries the manifest (`@__ofs_refract_manifest`: typed-tree hash and signature of each vein, global types, `monolith` layouts, `extern`s, variants) and the `geophone` agent (stdlib `geophone.ofs`, attached by `ofscc`). The lib gets `-soname lib<name>.so` so the patch can link against it. **Without `--refract` none of this exists**: the IR is identical to before.
2. **Agent (`geophone`).** Starts as a library constructor on the main thread and listens on the abstract Unix socket `ofs-refract.<package>`. The socket is added to the main thread's looper (`ALooper_addFd`), so a patch is applied **between two events** and the runtime (not thread-safe) never sees another thread. Log: `adb logcat -s ofs-refract`.
3. **PC (`ofs refract --remote`).** Builds with `--refract`, installs and opens, `adb forward tcp:7341 localabstract:ofs-refract.<package>`, connects, asks for the manifest and watches the `.oal` and the user's `.ofs` files. On save: `oalc` (for `.oal`), `ofscc` in patch mode (`OFSCC_REFRACT=patch`: vein-by-vein diff against the app's manifest plus the rules below), NDK `clang` (`--target=aarch64-linux-android26 -shared -fPIC -Wl,-Bsymbolic -Wl,--no-undefined`, linked against the app's `lib<name>.so`), sends the `.so` and prints the app's reply.
4. **In the app.** The `.so` goes to `code_cache/ofs-refract/`, is opened with `dlopen`, and `__ofs_refract_install` stores the new veins' addresses in the cells. The patch's globals are the app's (`external`, same address): state carries on. Then the agent calls `oal.refresh()` (OAL apps) or requests a frame.

**What goes in and what is refused.** Changed vein with the same signature: swapped. New vein: goes into the patch (no cell in the app); it and its callers are re-sent in every following patch. Removed vein: stays in the app, unused. New `monolith`, new `extern` and variants appended at the end: accepted. **Refused** (the app keeps the previous version; the message gives the reason and asks for a reinstall): new signature for a vein with a cell, new global or global with a new type, changed layout of an existing `monolith` (the native app does not migrate instances), `extern` with a new signature, removed or reordered variants. Compile error: nothing is sent. A patch using a symbol the app lacks (a new stdlib `attach`) fails to link on the PC, naming the symbol. Changes to the `.oal` header (`app`/`version`/`permission`) ask for a reinstall.

**Limits.** A running vein finishes in the old version (no native OSR). A stored vein value (callback handed to C, `fault_addr`) points at the build's version: the PC warns. Each patch's `.so` stays loaded until the process ends. aarch64/API 26+ only.

**Security.** The agent only exists in `--refract` builds (never in a normal or release build). The socket is abstract and local: from outside the device only `adb` reaches it, and the agent only accepts the `adb` uid (shell, 2000), root or the app itself (`SO_PEERCRED`); others are refused and logged. Anyone with `adb` access can inject code into the app: it is the same trust boundary as `adb`/`run-as`; do not ship a `--refract` APK.

**Protocol v1** (text lines ending in `\n`): on connect the app sends `OFS-REFRACT 1 <package> <pid> <generation>`; `MANIFEST` → the manifest lines and `END`; `PATCH <generation> <n>` followed by `n` bytes of the `.so` → `OK <generation> <ms> <veins>` or `ERR <generation> <reason>`; `PING` → `PONG`; `BYE` closes. Manifest: one record per line, tab-separated fields (`V <symbol> <hash> <signature> <1|0 cell>`, `G <global> <type>`, `M <monolith> <fields>`, `X <extern> <shape>`, `S - <variants>`); the app merges each patch's records (key = first two fields), so the PC always diffs against what is running.

Variables: `OFS_REFRACT_PORT` (PC port, 7341), `OFS_REFRACT_PERIOD` (ms between checks, 300), `OFS_REFRACT_ONCE=1` (exit after the first applied or refused patch). Device test: `ofs/tests/refract/android.sh` (skips without a device).

## Windows

The same command works on Windows (`src/packaging/windows/ofs.ps1`, `Invoke-AndroidBuild`; same steps as Linux). Requirements besides OFS itself:

| Item | Where / how to install |
|---|---|
| LLVM (`clang` on PATH) | `winget install LLVM.LLVM` (builds `oalc` for the host) |
| Android SDK | default `%LOCALAPPDATA%\Android\Sdk` (Android Studio) or `ANDROID_SDK`/`ANDROID_HOME`/`ANDROID_SDK_ROOT` |
| NDK | `ndk\<version>\toolchains\llvm\prebuilt\windows-x86_64\bin\clang.exe` (`sdkmanager "ndk;29.0.14206865"`; or `ANDROID_NDK`) |
| build-tools | `build-tools\<version>\aapt2.exe`, `zipalign.exe`, `apksigner.bat` (`sdkmanager "build-tools;37.0.0"`) |
| `platforms` | `platforms\android-*\android.jar` (`sdkmanager "platforms;android-34"`) |
| JDK 17+ | `keytool`, `jar` and `apksigner`; found via `JAVA_HOME`, `Program Files\Android\Android Studio\jbr`, Adoptium/Microsoft/Zulu or PATH |

```powershell
ofs build --target android app.oal -o app-debug.apk
ofs build --target android app.oal --install --serial <device>
```

Differences from Linux: the cache (`ofscc` with `OFSCC_TARGET` if the installed one is older, `oalc.exe`, `magma-aarch64.o`) lives in `%LOCALAPPDATA%\ofs\android\`; the debug key is `%USERPROFILE%\.android\debug.keystore` (or one generated in the cache with `keytool`); `lib/` is stored uncompressed using the JDK `jar` (no `zip`). The installer ships `tools\`, `stdlib\runtime\` and the `ofscc\` sources for this; `OFS_SOURCE=<repo>\ofs` uses a checkout. Errors say what is missing and the `sdkmanager` command to install it. Status: verified by review against the Linux flow and by an informational CI job (`android-windows` in `build.yml`).

## Runtime model (stdlib `android.ofs`)

- **Entry:** `android.ofs` exports `vein ANativeActivity_onCreate(...)`, which `NativeActivity` finds through `dlsym`. It fills `activity->callbacks` with the addresses of OFS veins using `fault_addr` (see [LANGUAGE_REFERENCE.md](LANGUAGE_REFERENCE.md)).
- **Single thread:** everything runs on the Android main thread, with no pthread. The magma runtime is not thread-safe, so this is intentional.
  - lifecycle: `onStart/Resume/Pause/Stop/Destroy`, `onWindowFocusChanged`, `onNativeWindow*`, `onInputQueue*`, `onContentRectChanged`, `onConfigurationChanged`, `onLowMemory` callbacks;
  - input: `AInputQueue_attachLooper` on the main thread's looper, with an OFS callback;
  - frames: `AChoreographer_postFrameCallback` (API 24+), rescheduled only on request (`android.request_frame()` or `android.continuous = true`).
  - Long work must be split into chunks, one per `EV_FRAME`.
- **Contract:** the program defines `vein android_event(ev: stone) -> void` and reads state from `android.*`:

```ofs
attach {F:android.ofs}

vein android_event(ev: stone) -> void {
    if (ev == android.EV_FRAME) {
        if (android.lock()) {
            android.fill_rect(0, 0, android.buf_w, android.buf_h, 1052704)
            android.unlock_post()
        }
    }
    if (ev == android.EV_TOUCH_DOWN) { android.request_frame() }
    if (ev == android.EV_BACK) { android.finish() }
}
```

| Events | State |
|---|---|
| `EV_CREATE`, `EV_START`, `EV_RESUME`, `EV_PAUSE`, `EV_STOP`, `EV_DESTROY` | `activity`, `sdk_version`, `resumed` |
| `EV_WINDOW_CREATED`, `EV_WINDOW_DESTROYED`, `EV_RESIZE`, `EV_ROTATE`, `EV_FRAME` | `window`, `win_w`, `win_h`, `orientation`, `content_*`, `frame_ns` |
| `EV_TOUCH_DOWN/UP/MOVE/CANCEL`, `EV_POINTER_DOWN/UP` (other fingers) | `touch_id`, `touch_x`, `touch_y`, `touch_count`; all fingers in `ptr_count`, `ptr_id[]`, `ptr_x[]`, `ptr_y[]` |
| `EV_BACK` (back key released), `EV_KEY` | `key_code`, `key_action` |
| `EV_FOCUS`, `EV_CONFIG`, `EV_LOW_MEMORY` | `has_focus` |

Functions: `lock()`/`unlock_post()` (RGBA_8888 buffer of the `ANativeWindow`: `buf_w`, `buf_h`, `buf_stride`, `buf_bits`), `fill_rect`, `blit(pixels, w, h)` (copies a `Canvas` buffer), `request_frame()`, `finish()`, `set_orientation(ORIENT_REQ_*)` (JNI `setRequestedOrientation`), `call_activity_void_int(name, value)`, `internal_data_path()`, `external_data_path()`, `log(text)`, `log_tag(tag, text)`, `s32(v)`, `peek`/`poke`.

**Multitouch:** each event applies to finger `touch_id` (`AMotionEvent_getPointerId`). The first finger generates `EV_TOUCH_DOWN`, the following ones `EV_POINTER_DOWN`; on release, `EV_POINTER_UP` (fingers remain) or `EV_TOUCH_UP` (the last one). `EV_TOUCH_MOVE` arrives once per finger.

**JNI (main thread, through the `JNIEnv` table with `fault_call`):** `jni_env()`, `jni_activity()`, `jni_fn(i)`, `jni_find_class(name)`, `jni_string(s)`, `jni_to_text(jstring)`, `jni_delete(ref)`, `jni_check()` (clears an exception), `jni_args(a, b, c, d)` (jvalue), `jni_static_bool(class, method)`, `package_name()`, `start_intent(action, uri)`.

- `android.is_external_storage_manager()`: `Environment.isExternalStorageManager()` (Android 11+; earlier it returns true).
- `android.open_all_files_settings()`: opens `Settings.ACTION_MANAGE_APP_ALL_FILES_ACCESS_PERMISSION` with `package:<package>` (with fallbacks). In the `.oal`: `permission android.permission.MANAGE_EXTERNAL_STORAGE`.
- `android.keep_screen_on(bool)`: `FLAG_KEEP_SCREEN_ON`.
- `android.set_immersive(bool)`: immersive full screen (hides status and navigation bars; `setSystemUiVisibility` with `IMMERSIVE_STICKY` via JNI); re-applied automatically when the window regains focus.
- `android.set_cutout_short_edges(bool)`: Android 9+: also draw in the camera cutout strip (`layoutInDisplayCutoutMode = SHORT_EDGES`), with no black strip in landscape.
- `android.jni_call_object(obj, name, signature)` / `jni_call_void1(obj, name, signature, arg)`: generic calls with no argument / with 1 argument.
- `android.asset_read("file")`: reads `assets/` from the APK (`AAssetManager`); size in `android.asset_len`.
- `android.redraw_needed`: the window was created/resized/redrawn: the program must copy the frame again (the OAL backend only copies when something changed).

**Audio (`audio_android.ofs` + `wav.ofs`):** `audio.open()` opens a 44.1 kHz stereo i16 AAudio stream with a callback; `audio.play(channel, wav.load(...) or wav.decode(ptr, n), loop)`, `stop`, `stop_all`, `set_volume(channel, %)`, `set_master(%)`, `playing(channel)`, `pause`/`resume`/`close`, `pump()` once per frame. The mixer runs on the audio thread and only touches raw memory (no Arrays/strings); replaced PCM is freed after a safe delay. `wav.ofs` decodes 8/16-bit PCM and **Microsoft ADPCM** (output identical to ffmpeg's). The CLI links `-laaudio`.

The back button is delivered as `EV_BACK` and does **not** close the app by itself: call `android.finish()` (OAL does it by default).

### Text input via the system keyboard (`android_input.ofs`)

`ainput.open(title, text, multiline)` opens an `android.app.Dialog` with a JNI-created `EditText` (no Java of our own): default keyboard (Gboard), cursor, paste and autocomplete. No listeners: the buttons are `ToggleButton`s (they toggle on tap; `ainput.poll()` reads `isChecked()`), and back/tap outside closes the Dialog (`isShowing()`). `poll()` returns 0 open, 1 OK, 2 cancelled; `ainput.text()` reads the text. OAL exposes it as `oal.edit_open`.

## Current limits

- `arm64-v8a` (aarch64) only and API 26+. No x86/armv7.
- Software rendering (`ANativeWindow_lock`), no OpenGL/Vulkan.
- Audio: WAV only (PCM/MS-ADPCM); no Ogg/MP3; no quality resampling (integer 16.16 step).
- No `onSaveInstanceState` (the app saves its own state in `on pause`).
- The offsets of C structs (`ANativeActivity`, `ANativeWindow_Buffer`, `ARect`, `struct stat`/`statfs`, `JNIEnv` table) are fixed for aarch64.
- 32-bit C integers arrive as `stone` with undefined upper bits: use `android.s32()`.
- `fault_call` only passes integers and pointers (no `float`/`double`).
- The installed `ofs/dist/magma.o` and `ofscc` still predate the Android target: until the next release, the CLI builds `ofscc` from source.

## Generic JNI, WebView, HTTP (stdlib)

- **Generic JNI** (`android.ofs`): `jni_call(obj, name, signature, a..f)` (the return kind comes from the signature: `V`, `Z`, `I`, `J`, object), `jni_new(class, signature, a..d)`, `jni_scall(class, name, signature, a..d)` (static), `jni_static_int_field`, `jni_global`/`jni_delete_global`, `jni_new_byte_array`/`jni_get_bytes`/`jni_set_bytes`, `jni_new_object_array`/`jni_set_object_elem`; `android.jni_failed` tells whether a Java exception happened. Main thread only.
- **`android_webview.ofs`**: `webview.open(base_url, html)` opens a `WebView` (JS, DOM storage, file access, media without gesture) in a full-screen immersive `android.app.Dialog`; `poll()` (Back closes the Dialog), `eval(js)`, `title()`, `pause(on)`, `close()`. **Why a Dialog:** `NativeActivity` takes the main window surface (`takeSurface`), so a `View` added to its window is not drawn; the Dialog has its own window and gets touch directly (not through `AInputQueue`). No Java subclass: the shim goes in as a `<script>` in the HTML (`loadDataWithBaseURL("file:///folder/", html)`), and the JS-to-OFS return channel is `document.title` (Chromium cuts titles at 4096 characters and collapses whitespace/control chars: send in chunks and with `encodeURIComponent`). `EV_FRAME` keeps arriving while the main window is covered. `ofs_str_char_at` is O(n): read bytes by pointer on large texts.
- **`android_http.ofs`**: `ahttp.open(url)`/`read(buf)`/`close()` and `get_text(url)` over `HttpURLConnection` (HTTPS with certificate checking and redirects; the OpenSSL of `tls.ofs` cannot be linked in an APK). Blocks up to ~4 s per call on the main thread (use short per-frame steps; `StrictMode` is relaxed). Needs `permission INTERNET` in the `.oal`. Accepts `file:///...` and absolute paths.

## Engine mode: hosting other code/Views in the NativeActivity (stdlib `android.ofs`)

To run a game engine (SDL, Godot) **inside** the app, without installing an APK and without Java in the APK (`hasCode=false`):

- `release_window()`: calls `getWindow().takeSurface(null)` and `takeInputQueue(null)`. **Call it in `EV_CREATE`** (the window is attached only after `onResume`). From then on the `NativeActivity` no longer claims the surface or the input queue: `set_content_view(view)` (or a Java adapter's `setContentView`) draws normally and gets touch/keys through Java. OFS stops receiving `EV_WINDOW_*` and touches; lifecycle events still arrive. Tested on Android 11 (Moto G8 Power). In AOSP's `NativeActivity.java`, `onCreate` calls `takeSurface(this)`/`takeInputQueue(this)` before `ANativeActivity_onCreate`; `ViewRootImpl` reads those callbacks when the window is attached, so `null` wins.
- `dex_load_class(dex, libs_dir, "pkg.Class")`: `DexClassLoader` (parent: the activity's class loader) + `loadClass`; returns a **global** class reference or 0 (reason in `jni_error`). `dex` accepts several files separated by `:`. The `.dex` must live in the app's internal storage and, on Android 14+, be read-only (`set_read_only(path)`). `libs_dir` is that loader's `System.loadLibrary` search path.
- `jni_scall_cls(cls, name, signature, a..d)`: static method on an already obtained `jclass` (e.g. from `dex_load_class`).
- `jni_take_error()`: if a Java exception is pending, stores its `toString()` in `jni_error`, prints the stack to logcat (`System.err`) and clears it.
- `intent_extra(key)`: `getIntent().getStringExtra(key)` ("" if missing).
- `self_intent(keys, values)` / `restart_process(keys, values)`: `Intent` for this same activity with `String` extras and `FLAG_ACTIVITY_NEW_TASK|CLEAR_TASK`; `restart_process` calls `startActivity` and kills the process (`Process.killProcess(myPid)`): the system opens the activity in a fresh process (~60 ms on a Moto G8). M.O.O.N uses it to enter and leave "engine mode" (one engine per process).
