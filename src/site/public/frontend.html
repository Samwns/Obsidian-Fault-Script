Posicao tecnica

ODL/OES existem para a OFS ter linguagens web proprias. O target web atual permite compatibilidade com navegadores, mas a fonte do projeto nao e HTML/CSS.

Fonte

O autor escreve .odl e .oes. Esses arquivos sao a linguagem do projeto.

Target

HTML/CSS/JS sao artefatos gerados para navegadores e hospedagens existentes.

Hospedagem

GitHub Pages, nginx, CDN e webserver OFS servem o target, nao definem a linguagem.

Inspecao

ODL/OES tambem podem ser publicados como fonte com MIME proprio para ferramentas.

O que falta construir

Para competir com frameworks maduros, a proxima etapa e adicionar componentes tipados, runtime incremental, roteamento, build incremental e validadores de UI.

Componentes tipados

Adicionar props, slots, estado local e verificacao de contrato entre componentes.

Hidratacao

Gerar pontos de montagem para comportamento sem reescrever o documento inteiro.

Roteamento

Mapear rotas de paginas ODL e endpoints OFS no mesmo projeto.

Build incremental

Recompilar somente arquivos alterados e dependentes diretos no Go Live.

Acessibilidade

Validar nomes, contraste, landmarks e foco antes de publicar.

Pacotes web

Distribuir componentes ODL/OES versionados pela mesma logica de packages.

Como roda hoje

OFS pode gerar arquivos estaticos ou servir documentos gerados por um binario nativo. O browser continua recebendo formatos que entende; ODL/OES continuam sendo a fonte.

site.ofs
attach {odl}
attach {oes}
attach {webserver}

core main() {
    forge head = odl.css("site.css")
    forge body = odl.main("app", odl.h1("Documento ODL"))
    forge html = odl.document("pt", "OFS", "site", head, body)
    webserver.serve_html_forever(8080, html)
}

Traducao e interoperabilidade

O tradutor ajuda a migrar codigo existente. Ele nao deve ser tratado como conversao perfeita: a saida deve ser revisada e ajustada para o modelo ODL/OES.

build
ofs odl page.odl -o index.html
ofs oes theme.oes -o site.css
ofs translate legacy.html --to odl
ofs translate legacy.css --to oes
