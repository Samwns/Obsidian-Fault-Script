    Guia Arquitetural — OFS IDLE (Obsidian Integrated Development & Learning Environment)

    Nesta página

    Este documento estabelece o mapeamento técnico e a especificação de engenharia reversa para a construção da OFS IDLE: um ambiente de desenvolvimento integrado de altíssima performance, com a mesma interface, elegância e ergonomia do Visual Studio Code, porém 100% desenvolvido em Obsidian Fault Script (OFS) e renderizado nativamente via Obsidian Layout Language (OLL), sem utilizar Electron, Chromium, Node.js ou código proprietário da Microsoft.

    1. Princípios de Soberania e Sala Limpa (Clean-Room)

    1. Zero Linhas de Código da Microsoft: O código da OFS IDLE é escrito inteiramente do zero na sintaxe do OFS (vein, forge, monolith, attach), utilizando a stack nativa Magma (Canvas, Window, OLL, FS).
    2. Zero Créditos Obrigatórios: Conceitos arquiteturais (Activity Bar, Sidebar em árvore, abas de editor com gutter numerado, painel inferior de terminal e status bar) são padrões universais da indústria de software (adotados por Eclipse, TextMate, Sublime Text, Atom, Theia, Lapce e Zed). Como nenhuma linha de código em TypeScript/JS do VS Code é copiada, a autoria intelectual é integralmente do projeto OFS.
    3. Ícone Oficial da Linguagem: A identidade visual substitui todo e qualquer símbolo externo pelo Diamante de Obsidiana com Fenda de Energia (OFS Logo) em alta resolução.

    2. Comparativo Tecnológico: VS Code vs. OFS IDLE

    Dimensão TécnicaVS Code OficialOFS IDLE (Nativa)
    Engine de ExecuçãoNode.js + V8 Engine + Chromium RuntimeBinário Nativo AOT (Compilado via LLVM)
    Camada de Interface (UI)Web DOM + CSS + HTML5 CanvasOLL Declarativa + Buffer Nativo Magma / Win32 / X11
    Consumo de Memória (RAM)600 MB a 1.8 GB em repouso18 MB a 35 MB de memória total
    Tempo de Inicialização2.5 a 6.0 segundos15 a 45 milissegundos (instantâneo)
    Dependências ExternasNode, npm, Electron, Bibliotecas C++ pesadasZero dependências (executável único autocontido)
    Taxa de Quadros (FPS)Varia com o peso do DOM do Chromium60 FPS cravados com aceleração de desenho GDI/Xlib

    3. Mapeamento Arquitetural: VS Code → OFS IDLE

    O VS Code organiza seu núcleo no diretório src/vs/workbench/browser/parts/. A tabela abaixo mapeia cada módulo original para sua contraparte no ecossistema OFS:

    Componente VS CodeMódulo no VS CodeImplementação na OFS IDLEPapel no Sistema
    Titlebarparts/titlebaridle_titlebar.ofsMenu Superior (Arquivo, Editar, Ver), Ícone OFS e Caixa de Busca Global (Ctrl+P)
    Activity Barparts/activitybaridle_activitybar.ofsFaixa vertical esquerda (48px) com botões para Explorer, Busca, Git, Debug e Extensões
    Sidebarparts/sidebaridle_sidebar.ofsPainel retrátil (230px) com árvore hierárquica de arquivos do projeto via fs.ofs
    Editor Groupparts/editoridle_editor.ofsAbas de arquivos, Gutter com números de linha, Buffer de texto editável e Minimapa
    Panel / Terminalparts/panelidle_terminal.ofsPainel inferior com abas de Terminal Integrado, Saída de Compilação e Diagnósticos
    Status Barparts/statusbaridle_statusbar.ofsRodapé com Git branch, Erros/Alertas, Posição do cursor (Ln/Col), UTF-8 e status LSP
    Command Paletteplatform/quickinputidle_quickopen.ofsJanela suspensa modal centralizada para execução de comandos e busca rápida de arquivos

    4. Estrutura do Workbench em OLL (.oll)

    A árvore declarativa que compõe toda a interface visual da OFS IDLE segue o modelo moderno: 

    window "Obsidian Fault Script — Studio IDLE" {
    width: 1280
    height: 800
    auto_center: true
    resizable: true
    bg_color: #181818

    column {
        // 1. Barra de Título (Title Bar)
        row {
            height: 35
            bg_color: #1f1f1f
            padding: 6
            align: "space-between"
            // Menu: Arquivo, Editar, Seleção, Ver, Ir, Executar, Terminal, Ajuda
            // Busca Central: "Obsidian Fault Script - Studio (Ctrl+P)"
            // Controles de Janela: Minimizar, Maximizar, Fechar
        }

        // 2. Área Central de Trabalho (Workbench Principal)
        row {
            // Activity Bar: 48px
            column {
                width: 48
                bg_color: #181818
                padding: 6
                gap: 16
                // Ícones: Explorer (ativo), Search, Source Control, Run & Debug, Extensions, Settings
            }

            // Sidebar: 240px
            column {
                width: 240
                bg_color: #1f1f1f
                padding: 10
                gap: 8
                // Header: EXPLORER
                // Projeto: OBSIDIAN-FAULT-SCRIPT
                // Tree View: src/, docs/, ofs/, main.ofs, oll.ofs
            }

            // Editor Central e Terminal
            column {
                // Barra de Abas do Editor
                row {
                    height: 35
                    bg_color: #181818
                    // Aba ativa: [OFS] main.ofs (com 'x')
                    // Aba inativa: [OFS] oll.ofs
                }

                // Buffer do Código Fonte com Gutter Numerado
                row {
                    // Gutter com números de linha (1..35)
                    column { width: 45 bg_color: #1e1e1e }
                    // Área do Código com Colorização Sintática
                    card { bg_color: #1e1e1e padding: 8 }
                    // Minimapa do Código à direita
                    column { width: 55 bg_color: #1e1e1e }
                }

                // Painel Inferior (Terminal e Saída)
                card {
                    height: 180
                    bg_color: #181818
                    border_color: #2b2b2b
                    // Abas: TERMINAL (ativo), SAÍDA, PROBLEMAS (0), DEBUG
                    // Console com comandos do compilador ofs
                }
            }
        }

        // 3. Barra de Status Inferior (Status Bar)
        row {
            height: 24
            bg_color: #007acc  // ou roxo OFS #6d28d9
            padding: 4
            align: "space-between"
            // Esquerda: Git branch, erros (0), avisos (0), OFS LSP Pronto
            // Direita: Ln 14, Col 28 | 4 Espaços | UTF-8 | LF | Obsidian Fault Script
        }
    }
}

    5. Próximos Passos de Construção da IDLE

    1. Protótipo Visual e Operacional Nativo (`idle/src/ofs_idle.ofs`): Criação da aplicação completa em OFS nativo desenhando com alta fidelidade o Workbench do VS Code, ícones vetoriais em OFS puro e tipografia ClearType.
    2. Integração com Compilador e Ferramentas: Conectar o terminal integrado da IDLE diretamente com ofs build, ofs run e ofs ui.
    3. Gerador de Binário: Compilar a IDLE para executável Windows (ofs_idle.exe) e Linux (ofs_idle).
