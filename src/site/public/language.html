Modelo da linguagem

OFS é uma linguagem compilada e estaticamente tipada. O compilador self-hosted expande imports, analisa tokens, monta AST, valida tipos e gera LLVM IR nativo. `core main()` define o ponto de entrada do executável.

hello.ofs
attach {math}

vein add(a: stone, b: stone) -> stone {
    return a + b
}

core main() {
    forge result: stone = add(20, 2)
    echo(result)
}

Sistema de tipos

Tipos primitivos cobrem números, texto e lógica. Inteiros com largura explícita auxiliam FFI e dados binários. Arrays armazenam elementos homogêneos, e monoliths definem registros de dados.

TipoRepresentação e usoExemplo
stoneInteiro principal de 64 bits com sinal.forge n: stone = 42
crystalPonto flutuante de 64 bits (IEEE 754).forge pi: crystal = 3.14
obsidianTexto imutável terminado em zero no runtime.forge name = "OFS"
boolValor lógico booleano (true ou false).forge ready = true
u8..u64 / i8..i32Inteiros com largura explícita de bits.forge channel: u8 = 255
Array<T>Coleção dinâmica homogênea.forge values = [1, 2, 3]
monolithEstrutura nomeada de campos tipados.monolith Point { x: stone }

Variáveis, constantes e atribuição

`forge` aloca variáveis locais ou globais, com tipo inferido ou explícito. `const` expressa valores que não podem ser reatribuídos.

FormaComportamento
forge name = valueCria variável local com tipo inferido.
forge name: Type = valueCria variável com tipo explicitamente declarado.
const name: Type = valueDeclara valor constante imutável.
=, +=, -=, *=, /=Atribuição simples e composta.
++ / --Incremento e decremento inteiros.

Operadores e conversões

A precedência segue o padrão de linguagens modernas: aritmética antes de comparação e lógica. Conversões de tipo usam `as` de forma explícita.

GrupoOperadoresResultado
Aritmética+ - * / %Opera números; + também concatena texto.
Comparação== != < <= > >=Produz bool.
Lógica&& || !Combina ou inverte condições.
Bits& | ^ << >>Opera sobre representação binária de inteiros.
Ponteiro&value *pointerObtém endereço e acessa o valor apontado em contexto de baixo nível.
Conversãovalue as TypeConversão explícita validada pelo verificador de tipos.

Funções, intents e lambdas

`vein` declara funções nomeadas ou anônimas. Parâmetros e retornos possuem tipos explícitos. Intents como `intent pure` documentam contratos de função.

functions.ofs
vein square(x: stone) -> stone intent pure {
    return x * x
}

vein apply(x: stone, fn: vein(stone) -> stone) -> stone {
    return fn(x)
}

core main() {
    forge double = vein(x: stone) -> stone {
        return x * 2
    }
    echo(apply(5, double))
}

Controle de fluxo

`if/else` controla bifurcações condicionais, `while` repete enquanto uma condição for verdadeira e `cycle` fornece laço estruturado com contador.

flow.ofs
if (score >= 10) {
    echo("ok")
} else {
    echo("retry")
}

while (running) {
    tick()
}

cycle (forge i = 0; i < 10; i++) {
    echo(i)
}

Arrays e indexação

Literais de array criam coleções homogêneas indexadas a partir de zero. Leitura e escrita usam colchetes, e `ofs_array_len` retorna a quantidade de itens.

collections.ofs
forge values = [10, 20, 30]
values[1] = 25

cycle (forge i: stone = 0; i < ofs_array_len(values); i++) {
    echo(values[i])
}

Monolith, impl, namespace e strata

`monolith` declara o layout de dados, `impl` agrupa métodos associados, `namespace` organiza símbolos e `strata` define variantes etiquetadas.

point.ofs
monolith Point {
    x: stone
    y: stone
}

impl Point {
    vein sum(self) -> stone {
        return self.x + self.y
    }
}

Tremor, catch e throw

`throw` interrompe a execução com um valor de erro. `tremor` delimita o bloco monitorado e `catch` intercepta a falha capturada.

errors.ofs
vein require_positive(value: stone) -> stone {
    if (value < 0) {
        throw "negative value"
    }
    return value
}

core main() {
    tremor {
        echo(require_positive(-1))
    } catch (message: obsidian) {
        echo(message)
    }
}

Módulos e importação

`attach {nome}` busca módulos da biblioteca padrão e pacotes; `attach {F:caminho}` inclui arquivos locais. `extern vein` declara chamadas externas de runtime ou C.

attach {math}

Importa funções da biblioteca padrão por nome.

attach {F:path/file.ofs}

Importa um arquivo OFS local explicitamente.

extern vein

Declara símbolos oferecidos pelo runtime ou por C.

core main()

Define o ponto de entrada do programa nativo.

Baixo nível: ponteiros, memória e intrinsics

Recursos de baixo nível na OFS são explícitos e opt-in. Eles permitem controle preciso de registradores e memória sem comprometer a clareza da linguagem padrão.

fracture { ... }

Abre o contexto tipado de ponteiros. Nele, shard p: *stone = &x cria um ponteiro e *p lê ou escreve o valor apontado. O compilador continua verificando os tipos, mantendo a responsabilidade de tempo de vida no código.

abyss { ... }

Marca operações cruas e irrestritas. Serve como demarcação explícita no código-fonte para operações de baixo nível que assumem risco manual de memória.

bedrock { ... }

Contexto tipado para intrinsics de máquina e gerenciamento direto de memória: regiões lineares, alinhamento, barreiras e funções fault_*.

intent fractal

Qualificador de efeito posicionado na assinatura de funções para registrar intenção funcional sem alterar o parser estrutural.

tectonic fracture

Prefixo sintático aceito antes de blocos de baixo nível para demarcar limites de isolamento sem alterar a geração do backend LLVM.

fault_*

Intrinsics de máquina para manipulação de bits, contagem de zeros, rotações, swap de bytes, barreiras de memória e prefetch.

low-level.ofs
attach {bedrock}

core main() {
    forge region: *stone = bedrock_region_new(4)
    bedrock_region_write(region, 0, 10)
    bedrock_region_add(region, 0, 5)
    echo(bedrock_region_read(region, 0))
    bedrock_region_drop(region)
}
Regra de segurança: ponteiros e regiões manuais não possuem coleta automática; desalocações devem ocorrer exatamente uma vez através de funções apropriadas como bedrock_region_drop.

Comandos de compilação

`check` valida sintaxe e tipos; `run` compila e executa temporariamente; `build` gera o executável nativo; `ir` emite o LLVM IR; `asm` emite assembly.

terminal
ofs check app.ofs
ofs run app.ofs
ofs build app.ofs -o app
ofs ir app.ofs -o app.ll
ofs asm app.ofs -o app.s
Gerado por ODL e OES em OFS.
