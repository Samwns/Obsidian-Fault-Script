Modelo da linguagem

OFS e compilada e estaticamente tipada. O frontend self-hosted expande imports, cria tokens, monta AST, verifica tipos e gera LLVM IR. `core main()` define o executavel; bibliotecas podem conter apenas funcoes, tipos e constantes.

hello.ofs
// OFS source
vein add(a: stone, b: stone) -> stone {
    return a + b
}

core main() {
    forge result: stone = add(20, 2)
    echo(result)
}

Sistema de tipos

Tipos primitivos cobrem numeros, texto e logica. Inteiros de largura explicita ajudam FFI e dados binarios. Arrays guardam elementos do mesmo tipo, e monoliths agrupam campos nomeados.

TipoRepresentacao/usoExemplo
stoneInteiro principal de 64 bits.forge n: stone = 42
crystalPonto flutuante de 64 bits.forge pi: crystal = 3.14
obsidianTexto terminado em zero no runtime atual.forge name = "OFS"
boolValor logico.forge ready = true
u8..u64 / i8..i32Inteiros com largura explicita.forge channel: u8 = 255
Array<T>Colecao dinamica homogenea.forge values = [1, 2, 3]
monolithEstrutura nomeada com campos.monolith Point { x: stone }

Variaveis, constantes e atribuicao

`forge` cria armazenamento local ou global. O tipo pode ser inferido pelo inicializador ou escrito explicitamente. `const` expressa valor que nao deve ser reatribuido.

FormaComportamento
forge name = valueCria variavel com tipo inferido.
forge name: Type = valueCria variavel com tipo declarado.
const name: Type = valueDeclara valor constante.
=, +=, -=, *=, /=Atribuicao simples e composta.
++ / --Incremento e decremento de inteiros.

Operadores e conversoes

A precedencia segue a ordem comum: multiplicacao antes de soma, comparacoes antes de logica e atribuicao por ultimo. Use parenteses quando a ordem fizer parte da intencao do codigo. Casts com `as` sao explicitos; ponteiros exigem um contexto de baixo nivel.

GrupoOperadoresResultado
Aritmetica+ - * / %Opera numeros; + tambem concatena texto.
Comparacao== != < <= > >=Produz bool.
Logica&& || !Combina ou inverte condicoes.
Bits& | ^ << >>Opera a representacao inteira.
Ponteiro&value *pointerObtem endereco e acessa o valor apontado dentro de contexto baixo nivel.
Conversaovalue as TypeSolicita conversao explicita validada pelo type checker.

Funcoes, intents e lambdas

`vein` declara uma funcao. Parametros e retorno recebem tipos. `intent pure`, `impure` e `fractal` registram intencao sem substituir a verificacao de tipos. Funcoes podem ser valores e lambdas usam a mesma palavra `vein`.

functions.ofs
vein square(x: stone) -> stone intent pure {
    return x * x
}

vein apply(x: stone, fn: vein(stone) -> stone) -> stone {
    return fn(x)
}

core main() {
    forge double = vein(x: stone) -> stone {
        return x * 2
    }
    echo(apply(5, double))
}

Controle de fluxo

`if/else` escolhe caminhos, `while` repete enquanto a condicao for verdadeira e `cycle` oferece inicializacao, condicao e passo. `break` e `continue` atuam sobre o loop atual; `return` encerra a funcao.

flow.ofs
if (score >= 10) {
    echo("ok")
} else {
    echo("retry")
}

while (running) {
    tick()
}

cycle (forge i = 0; i < 10; i++) {
    echo(i)
}

Arrays e indexacao

Literais de array inferem um tipo homogeneo. O indice comeca em zero, leitura e escrita usam colchetes e `ofs_array_len` informa o numero de elementos. O runtime verifica limites; acessar uma posicao inexistente e erro de execucao.

collections.ofs
forge values = [10, 20, 30]
values[1] = 25

cycle (forge i: stone = 0; i < ofs_array_len(values); i++) {
    echo(values[i])
}

Monolith, impl, namespace e strata

`monolith` define layout de dados; `impl` agrupa metodos; `namespace` organiza nomes; `strata` representa variantes etiquetadas em evolucao. Layout `packed` existe para integracao binaria explicita.

point.ofs
monolith Point {
    x: stone
    y: stone
}

impl Point {
    vein sum(self) -> stone {
        return self.x + self.y
    }
}

Tremor, catch e throw

`throw` interrompe o caminho atual com um valor de falha. `tremor` delimita o codigo observado e `catch` recebe a falha. O tipo escrito no catch documenta o contrato esperado; recursos manuais alocados antes da falha continuam sob responsabilidade do programa.

errors.ofs
vein require_positive(value: stone) -> stone {
    if (value < 0) {
        throw "negative value"
    }
    return value
}

core main() {
    tremor {
        echo(require_positive(-1))
    } catch (message: obsidian) {
        echo(message)
    }
}

Imports e fronteira externa

`attach {nome}` procura stdlib/pacotes; `attach {F:caminho}` inclui fonte local. `extern vein` declara simbolo do runtime ou biblioteca C. `rift vein` registra ABI externa experimental.

attach {math}

Importa funcoes da biblioteca padrao por nome.

attach {F:path/file.ofs}

Importa um arquivo OFS local explicitamente.

extern vein

Declara simbolos oferecidos pelo runtime ou por C.

core main()

Define o ponto de entrada do programa nativo.

Baixo nivel: ponteiros, memoria e intrinsics

O baixo nivel da OFS e opt-in e aparece no fonte. Esses blocos nao tornam um endereco valido, nao adicionam coleta de lixo e nao substituem liberacao de memoria. Use-os quando o contrato de tipos comum nao representa a operacao necessaria.

fracture { ... }

Abre o contexto tipado de ponteiros. Nele, shard p: *stone = &x cria um ponteiro e *p le ou escreve o valor apontado. O compilador continua verificando o tipo do ponteiro, mas validade de endereco e tempo de vida continuam sendo responsabilidade do programa.

abyss { ... }

Marca trabalho cru e irrestrito. A sintaxe ainda passa pelo mesmo parser e type checker atual, portanto nao desliga magicamente toda verificacao. O nome serve como fronteira explicita para codigo que aceita maior risco e nao oferece garantia adicional de memoria.

bedrock { ... }

Contexto tipado para os intrinsics de maquina e para a biblioteca bedrock: regioes, views, lanes, endian, prefetch e barreiras. Memoria criada por bedrock_cell_new ou bedrock_region_new deve ser liberada exatamente uma vez.

intent fractal

fractal e um intent de funcao, escrito depois do retorno. Ele registra a intencao de efeito da funcao; nao existe token de bloco fractal {} no parser atual. Intents ainda nao formam um sistema de efeitos com garantias estaticas completas.

tectonic fracture

tectonic e um prefixo aceito antes de fracture, abyss ou bedrock. Hoje ele preserva o mesmo bloco sem alterar a geracao LLVM. Nomes como tectonic safe e tectonic fractal nao sao formas suportadas.

fault_*

Intrinsics incluem contagem de bits, leading/trailing zeros, byte swap, rotacoes, stepping de ponteiro, corte e patch de campos, weave, fence e prefetch. Eles baixam diretamente para operacoes LLVM e exigem tipos e larguras validos.

low-level.ofs
attach {bedrock}

core main() {
    forge region: *stone = bedrock_region_new(4)
    bedrock_region_write(region, 0, 10)
    bedrock_region_add(region, 0, 5)
    echo(bedrock_region_read(region, 0))
    bedrock_region_drop(region)
}
Responsabilidade: nao desreferencie ponteiro nulo ou expirado, nao acesse fora de uma regiao, nao use uma regiao depois de bedrock_region_drop e nao libere a mesma alocacao duas vezes.

Do fonte ao executavel

`check` para apos analise; `run` gera binario temporario e executa; `build` grava o executavel; `ir` preserva LLVM IR; `asm` solicita assembly ao toolchain.

terminal
ofs check app.ofs
ofs run app.ofs
ofs build app.ofs -o app
ofs ir app.ofs -o app.ll
ofs asm app.ofs -o app.s
