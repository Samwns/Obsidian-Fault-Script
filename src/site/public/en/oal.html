OAL — Obsidian Android Language

An `.oal` file describes the manifest, touch screens, styles, actions and lifecycle; logic stays in `.ofs` (imported with `use` or `attach`). `oalc` generates `AndroidManifest.xml` and the OFS screen code.

app.oal
use "biblioteca.ofs"

app "M.O.O.N" "com.fixedseat.moon"
  version "0.1.0"
  permission internet

style button.primario
  fill #8b6cff
  ink #101020
  curve 24
  pressed fill #5f45c8

screen biblioteca
  bar "M.O.O.N"
    button.icon "plugins" -> abrir_plugins
  button.primario "Importar jogo" icon=import -> importar
  list jogos from biblioteca.jogos
    item title=item.nome sub=item.motor -> abrir_jogo(item)
    empty "Nenhum jogo ainda."

on back -> voltar

Building the APK

The CLI compiles for aarch64 with the NDK clang, links a `.so` with no C files and packages it with aapt2, zipalign and apksigner. Requirements and limits in docs/en/ANDROID.md.

terminal
ofs build --target android app.oal -o app.apk
ofs build --target android app.oal --install --serial 
ofs build --target android game.ofs --manifest AndroidManifest.xml

Runtime

Everything runs on the Android main thread: NativeActivity callbacks wired with `fault_addr`, input from the looper, frames from AChoreographer, software drawing (canvas, raster, ttf, icons) on the OLL layout core.

v0 capabilities

Full reference in docs/en/OAL_REFERENCE.md.

app

Manifest: name, package, version, icon, orientation, permissions, fullscreen.

screen

bar, button, button.icon, title, text, list, grid, card, row, portrait, landscape.

fab, dpad

Floating layer with opacity: floating buttons and a virtual D-pad.

style

fill, ink, curve, opacity and the pressed state: the CSS/OES role on Android.

on

back, pause, resume, rotate, low_memory dispatched to .ofs functions.

android.ofs

Pure-OFS NativeActivity: fault_addr, ALooper, AChoreographer, ANativeWindow, JNI.
